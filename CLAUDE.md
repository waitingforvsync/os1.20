# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

BBC Micro OS 1.20 (MOS) disassembly as 6502 assembly source for the BeebAsm assembler. The main source file is `os120.6502`, assembled via wrapper files. Reference ROM MD5: `0a59a5ba15fe8557b5f7fee32bbd393a`.

## Build and Verify

```bash
# Build original (must be byte-identical to reference ROM)
beebasm -i original.6502
md5sum OS120.rom    # must be 0a59a5ba15fe8557b5f7fee32bbd393a

# Build new version (OS 1.2B, with size optimizations, reports free bytes)
beebasm -i new.6502

# Verbose assembly (shows addresses and generated bytes)
beebasm -i original.6502 -v

# Run regression test (requires beebjit)
./test.sh
```

## Source Structure

- `os120.6502` — main source (~21K lines), organized into chapters by subsystem
- `original.6502` — sets `NEW_VERSION = FALSE`, includes os120.6502, SAVEs OS120.rom
- `new.6502` — sets `NEW_VERSION = TRUE`, includes os120.6502, SAVEs OS120new.rom
- `test.sh` — automated regression test using beebjit frame capture

Optimizations are wrapped in `IF NEW_VERSION ... ELSE ... ENDIF` blocks so the original ROM can always be reproduced exactly. The new version reports as "OS 1.2B" via `*FX 0`.

### Fixed addresses

Well-known addresses (OS entry points, extended vectors, MMIO credits, 6502 CPU vectors, multiply-by-640 table) are defined as constants and anchored with `SKIPTO` directives. These must not move.

### Important constraints

- This is ROM code — no self-modifying code. Use indirect addressing instead.
- Key data tables are spaced 16 bytes apart with padding bytes between them — do not remove padding.
- The `SAVE` directive is in the wrapper files, not in os120.6502.
- ZP &F8/&F9 are used by the new OSWORD 0 line editor (`editBufLen`/`editTemp`). They were previously unused and are safe from VDU driver clobbering (unlike &DA/&DB).
- The new OSWORD 0 reuses the tape CRC routine (`updateCRC` at &F7B0) for history recall. This is safe since tape cannot be active during line input.

## BeebAsm Syntax Notes

- Labels defined with `.labelName` at column 0; referenced as `labelName` (no dot)
- Constants defined as `name = value` (no dot prefix, unlike ACME's `.name = value`)
- Data: `EQUB`, `EQUW`, `EQUS` (not `!byte`, `!word`, `!text`)
- Hex prefix: `&` (not `$`)
- Lo/hi byte: `LO(expr)`, `HI(expr)`
- Accumulator mode must be explicit: `LSR A` not `LSR`
- Bitwise XOR operator: `EOR` (not `XOR`)
- No anonymous labels; converted to `._anonXXX` named labels
- No native big-endian word; use `EQUB HI(expr), LO(expr)`
- BeebAsm evaluates variable assignments immediately — no forward references in constants

## Conversion Origin

The source was mechanically converted from Toby Nelson's ACME-format disassembly (`os120_acme.a`) using `convert.py`. Both files are in `.gitignore` as they are not part of the deliverable. The BeebAsm source (`os120.6502`) is the canonical version going forward.
